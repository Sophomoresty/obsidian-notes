### 🧠 核心逻辑：谁在抢同一个坑位？

我们要证明：**映射到同一个组（Set）的主存块数量 $\le$ 路数（Ways）。**

#### 第一步：算“步长” (Stride in Sets)
也就是：**下一行数组的起始位置，相较于上一行，在 Cache Set 中跳了多少格？**

1.  **一行的大小：** $64 \text{ int} \times 4\text{B} = 256\text{B}$。
2.  **一个组的大小：** 题目没直接给，但我们知道 **块大小 (Block Size) = 32B**。
    * *注意：组号是根据块地址模运算得来的。*
3.  **一行的块数：** $256 / 32 = 8$ 个块。
4.  **结论：** 每一行的数据，在 Cache 里连续占据了 **8 个 Set**。
    * 比如：Row 0 占了 Set 0 ~ Set 7。
    * 那么 **Row 1 就会从 Set 8 开始**。
    * **步长 = 8 (Sets)。**

#### 第二步：算“轮回周期” (Period)
也就是：**走多少行，组号会回到原点（发生冲突）？**

1.  **Cache 总组数：** $8\text{KB} / (32\text{B} \times 4\text{路}) = 64$ 组。
2.  **回环公式：**
    $$T = \frac{\text{总组数}}{\text{步长}}$$
    $$T = \frac{64}{8} = 8$$
3.  **物理含义：** **每隔 8 行**，数组行的起始位置就会映射到同一个 Cache 组。
    * Row 0 $\to$ Set 0
    * Row 8 $\to$ Set 0 **(第1次碰撞)**
    * Row 16 $\to$ Set 0 **(第2次碰撞)**
    * Row 24 $\to$ Set 0 ...

#### 第三步：数“嫌疑人” (Contenders)
也就是：**在数组范围内，一共有几个“冤家”聚头了？**

1.  **数组总行数：** 24 行 (Row 0 ~ Row 23)。
2.  **聚头名单：**
    * Row 0
    * Row 8
    * Row 16
    * (下一个是 Row 24，但数组只有 24 行，即 0-23，所以 Row 24 不存在)。
3.  **嫌疑人总数：** **3 个**。

#### 第四步：终极判决 (Verdict)

* **战场：** Set 0 (以及其他任何 Set，逻辑相同)。
* **参战人数：** 3 个主存块 (来自 Row 0, 8, 16)。
* **Cache 容量（路数）：** **4 路** (也就是每个 Set 有 4 把椅子)。
* **判决：** **$3 < 4$**。
* **结论：** 椅子够坐！**不会发生替换！**

### 第二步：什么是“轮回周期”？ 🔄

现在的 Cache 总共有 **64 个组 (Set 0 ~ Set 63)**。
我们把 Cache 想象成一个**只有 64 个格子的圆盘**。

我们开始把数组一行一行地往里填：

1.  **Row 0 (第 1 行):**
    * 占领了 **Set 0 ~ Set 7**。
    * *(Cache 还空着 Set 8~63)*

2.  **Row 1 (第 2 行):**
    * 它是紧接着 Row 0 的。
    * 占领了 **Set 8 ~ Set 15**。

3.  **Row 2 (第 3 行):**
    * 占领了 **Set 16 ~ Set 23**。

... (一直填) ...

4.  **Row 7 (第 8 行):**
    * 占领了 **Set 56 ~ Set 63**。
    * **警报！** 到这里为止，Set 0 到 Set 63 **全部被占过一次了**。圆盘铺满了！

5.  **Row 8 (第 9 行) —— 轮回开始了！**
    * 它的块号继续增加，但是 `块号 % 64` 回到了起点。
    * 它**必须**回到 **Set 0 ~ Set 7** 去抢位置。

**这就是“轮回周期”：**
> **每过 8 行 (Row 0 ~ Row 7)，数组就会把整个 Cache 的 64 个组全部“摸”一遍。**
> 第 9 行 (Row 8) 不得不回到起点 (Set 0)，这就叫**一个周期结束，新的轮回开始**。

### 1. 为什么“偏移地址”不影响结论？

你担心的点是：“如果起始地址不是 0，是某个奇怪的偏移，会不会导致某一组冲突特别多？”

**答案是：不会。**

* **本质逻辑（数学证明）：**
    数组是连续存放的，它像一条长蛇。
    * **Cache 的结构：** 就像一个有 64 个格子的圆盘（64组）。
    * **蛇的盘绕：** 数组每隔 64 个主存块（$64 \times 32B = 2KB$），就会在 Cache 的组号上绕一圈，回到起点。
    * **数组总长度：** $6KB$。
    * **绕了几圈？** $6KB / 2KB = 3$ 圈。
    * **结论：** 无论蛇头（起始地址）从哪里开始，这条 6KB 长的蛇，最多只能在任何一个格子上**叠 3 层**（也就是占用 3 个路）。

**所以，偏移量只会决定“从哪个组开始叠”，不会改变“叠了几层”。** 只要叠的层数（3）小于 Cache 的路数（4），就永远不会溢出！

### 2. 你的解法复盘（满分思路）

你用的这个逻辑完全正确，且非常高效：

1.  **看容量：** Cache (8KB) > 数组 (6KB)。**（必要条件满足）**
2.  **看重叠（关键）：**
    * Cache 是 4 路组相联，相当于把 8KB 分成了 4 层，每层 2KB（也就是**直接映射的容量**）。
    * 数组 6KB，相当于要占 $6KB / 2KB = 3$ 层。
    * 因为 $3 < 4$（Cache 实际有 4 层），所以**完全装得下，且不会发生替换**。
3.  **算命中率：**
    * 既然不发生替换，那么只有**冷启动缺失（Compulsory Miss）**。
    * 也就是每个块第一次读的时候 Miss 一次，之后全是 Hit。
    * **Miss 次数：** 数组块数 = 192。
    * **总次数：** $24 \times 64 = 1536$。
    * **命中率：** $(1536 - 192) / 1536 = \mathbf{87.5\%}$。

### 3. 最终确认

* **数组 a 占用主存块：** 192 个。
* **命中率（原序）：** 87.5%。
* **命中率（调换序）：** **87.5%**。
