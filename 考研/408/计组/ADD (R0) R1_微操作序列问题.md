### **1. 暂存寄存器 (Y, Z) 的使用：谁能暂存？**

* **你的疑问**：是否只有源操作数才能放入暂存寄存器？或目的操作数（如 `R1`）的取值是否只能放在执行阶段？
* **最终理解**：
    * **没有限制**：暂存寄存器（如 `Y`, `Z`）是 CPU 内部的**临时存储空间**，可以存放**任何需要暂时保存的数据**，无论是从内存取出的数据、ALU 的中间结果，还是需要作为 ALU 输入的寄存器内容。
    * **优化时机**: “取操作数阶段”主要针对需要访问主存的操作数。

### **2. 寄存器之间能否直接传输？**

* **你的疑问**：寄存器内容不能直接写到另一个寄存器中，需要通过 `MDR` 中转吗？
* **最终理解**：
    * **可以直接传输**：CPU 内部的**通用寄存器之间可以直接进行数据传输**（例如 `(R1) -> Y`），这是 CPU 内部最基本、最高效的操作之一，不需要通过 `MDR`（`MDR` 主要用于内存交互）。

### **3. ALU 的角色：加法运算的数据通路**

* **你的疑问**：相加操作是否需要经过 ALU？数据通路怎么表示？
* **最终理解**：
    * **必须经过 ALU**：**所有算术和逻辑运算都必须通过 ALU (算术逻辑单元) 来完成**。ALU 是 CPU 内部专门负责这些计算的硬件模块。
    * **数据通路表示**：在微操作中，运算必须明确体现 ALU 的参与。例如，`(R1) -> ALU_Input1; (Y) -> ALU_Input2; ALUout -> Z` 明确表示了数据通过 ALU 运算后存入 `Z` 寄存器。

### **4. 指令中的寄存器号与地址码**
* **你的疑问**：对于 `ADD (R0), R1` 这样的指令，是否需要 `Ad(IR)` 来表示地址码？指令的地址码是什么？
* **最终理解**：
    * **指令有地址码**：指令中包含的寄存器号（如 `R0`, `R1`）本身就是指令**地址码/操作数字段**的一部分。
    * **解析而非 `Ad(IR)`**：在译码阶段，CPU 是从 `IR` 中**解析出**这些寄存器号。在微操作中，通常直接表示为 `(R0) -> MAR` 等，隐含了从 `IR` 解析并去通用寄存器堆读取寄存器内容的过程，**不需显式使用 `Ad(IR)`**。`Ad(IR)` 更多用于直接地址或偏移量。
