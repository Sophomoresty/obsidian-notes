### **3. 程序A和B的数据访问命中率：修正一个小细节**

* **关键参数：** 一个Cache块大小为 **64B**，一个`int`大小为 **4B**。
* **修正点：** 因此，一个Cache块可以存放 `64B / 4B = **16**` 个`int`元素。（你之前的分析中，可能沿用了上道题目的“4个”的结论，这里需要更新）。

现在我们用 **16个元素/块** 这个正确参数，重新分析命中率：

#### **程序A (按行访问 `a[i][j]`)**
* **访问模式：** `a[0][0], a[0][1], ..., a[0][15], a[0][16], ...`，内存地址**高度连续**。
* **Cache行为：**
    * 访问`a[0][0]`：**Miss**。加载包含`a[0][0]`到`a[0][15]`的第一个块。
    * 访问`a[0][1]`到`a[0][15]`：**Hit** (共15次Hit)。
    * 访问`a[0][16]`：**Miss**。加载包含`a[0][16]`到`a[0][31]`的第二个块。
    * 访问`a[0][17]`到`a[0][31]`：**Hit** (共15次Hit)。
* **规律：** 每访问 **16** 个连续的数组元素，会发生 **1次Miss** 和 **15次Hit**。
* **命中率 (Hit Rate):** `Hits / (Hits + Misses) = 15 / (15 + 1) = 15 / 16 = 93.75%`。

#### **程序B (按列访问 `a[i][j]`)**
* **访问模式：** `a[0][0], a[1][0], ..., a[255][0], a[0][1], ...`，内存地址**跳跃式**访问。
* **地址跳跃 (Stride):** 访问`a[i][j]`后接着访问`a[i+1][j]`，地址增加了 `256 * sizeof(int) = 256 * 4B = 1024B`。
* **Cache行为 (直接映射冲突):**
    * 块大小 = 64B。
    * Cache行数 = 8。
    * 地址跳跃 `1024B` 相当于跳跃了 `1024 / 64 = 16` 个主存块。
    * 当访问`a[i][j]`时，假设它映射到Cache行 `L = BlockNo(a[i][j]) mod 8`。

    * **结论：** 连续两次访问 (`a[i][j]` 和 `a[i+1][j]`) 总是映射到**同一个Cache行**！由于Cache只有8行，而内层循环要访问256个元素，这些元素会反复竞争并替换掉同一批（甚至可能只是同一条）Cache行中的内容。等外层循环`j`增加，访问`a[0][1]`时，它所需的数据块（与`a[0][0]`在同一个块）早就被`a[255][0]`那一轮访问替换掉了。
* **命中率 (Hit Rate):** 几乎每次访问都是**Miss**。命中率**接近 0%**。 （你的结论是正确的！）

### **程序B命中率为0%的逻辑阐述**

你已经证明了关键的一点：**对于固定的列 `j`，所有行 `i` 的元素 `a[i][j]` (即 `a[0][j]`, `a[1][j]`, ..., `a[255][j]`) 都映射到同一个Cache行 `m = (4 + ceil((4j+1)/64)) mod 8`**。

基于这个事实，我们可以清晰地阐述为什么命中率为0%：

1.  **内循环冲突 (Intra-column Conflict):**
    * 考虑内循环 `for(i=0; i<256; i++) sum += a[i][j];` 对固定列 `j` 的访问。
    * 访问 `a[0][j]` 时：假设Cache为空或是其他数据，这是一次 **Miss**。包含 `a[0][j]` 的块被加载到Cache行 `m`。
    * 访问 `a[1][j]` 时：由于 `a[1][j]` 与 `a[0][j]` 的地址相差 `1024B = 16 * 64B`，即相差16个主存块。它们映射到**同一个**Cache行 `m`。因为当前行 `m` 存放的是 `a[0][j]` 所在的块，所以访问 `a[1][j]` 必然发生**冲突Miss**。`a[1][j]` 所在的块会替换掉 `a[0][j]` 的块。
    * 访问 `a[2][j]` 时：同理，`a[2][j]` 也映射到行 `m`，发生**冲突Miss**，替换掉 `a[1][j]` 的块。
    * **结论：** 在内层循环对一整列进行访问时，**每一次访问都是一次Miss**，因为后一次访问总是将前一次加载的数据从那个唯一的Cache行中替换出去。

2.  **外循环无法利用空间局部性 (Inter-column Misses):**
    * 当外层循环 `j` 增加到 `j+1` 时，程序开始访问 `a[0][j+1]`。
    * `a[0][j+1]` 和 `a[0][j]` 的地址只相差 `4B`。如果 `j` 和 `j+1` 落在同一个16元素的块内（即 `floor(j/16) == floor((j+1)/16)`），它们本应在同一个Cache块中。
    * **但是**，在程序B的访问模式下，当访问 `a[0][j+1]` 时，Cache行 `m` （`a[0][j]` 所在的行）里存放的数据早就不是 `a[0][j]` 那个块了，而是内循环最后一次访问 `a[255][j]` 时加载进来的块。
    * 因此，即使 `a[0][j+1]` 和 `a[0][j]` 在同一主存块，访问 `a[0][j+1]` 时仍然是 **Miss**。
    * 如果 `j` 和 `j+1` 刚好跨越了一个块边界，那么 `a[0][j+1]` 本身就在一个新的块里，访问它自然也是 **Miss**。

3.  **最终结论：**
    无论是内循环的列访问，还是外循环切换到下一列的访问，几乎每一次对数组元素 `a[i][j]` 的读取都是一次Cache Miss。因此，程序B的**数据Cache命中率接近于0%**。

* 你写的 $5 + \lfloor \frac{j}{16} \rfloor \% 8$ 在计算上等价，不过写成 $(5 + \lfloor \frac{j}{16} \rfloor) \mod 8$ 在逻辑上更严谨一些呢（不过这不影响结果啦）。
