### 1. 你的推导核心（完全正确 ✅）

$$\text{累计执行次数} = \frac{m(m+1)}{2} = \frac{m^2 + m}{2}$$

但是，**数学是不会骗人的**。我们要把 $m \approx \sqrt{n}$ 代回到上面的式子里去。

$$T(n) = \frac{m^2 + m}{2} \approx \frac{(\sqrt{n})^2 + \sqrt{n}}{2}$$

重点来了：**$\sqrt{n}$ 的平方，不就是 $n$ 吗？**

$$T(n) \approx \frac{n + \sqrt{n}}{2} = \frac{1}{2}n + \frac{1}{2}\sqrt{n}$$

### 3. 最终判定

在时间复杂度的渐进表示法（Big-O）中，我们只保留**最高阶项**，并忽略系数。
* 这里有两项：$n$ 和 $\sqrt{n}$。
* 显然，$n$ 的增长速度远大于 $\sqrt{n}$。
* 所以，主导项是 $n$。

$$T(n) = O(n)$$

### 分块查找 (Block Search) 核心笔记

#### 1. 基本思想
将查找表分为若干子块。
* **块内无序：** 同一个块内的数据可以不按顺序排列。
* **块间有序：** 第 $i+1$ 块中所有关键字均大于（或小于）第 $i$ 块中的最大关键字。
* **索引表：** 为每个块建立一个索引项（包含：最大关键字，块起始地址）。**索引表本身是有序的**。

#### 2. 查找过程 (两步走)
分块查找的 ASL 由两部分组成：
$$ASL_{\text{成功}} = L_I + L_S$$

* **第一步 ($L_I$)：** 在索引表中确定待查记录所在的块（可顺序查找，也可折半查找）。
* **第二步 ($L_S$)：** 在块内顺序查找待查记录（通常只能顺序查找，因为块内无序）。

#### 3. 严谨计算公式

设表长为 $n$，均匀分成 $b$ 块，每块含有 $s$ 个记录。
即满足关系：$n = s \times b$ （$b$ 为索引表长度，$s$ 为块长）。

##### 情况一：索引表采用“顺序查找”
* **索引查找平均长度：** $L_I = \frac{b+1}{2}$
* **块内查找平均长度：** $L_S = \frac{s+1}{2}$
* **总 ASL：**
    $$ASL_{\text{成功}} = \frac{b+1}{2} + \frac{s+1}{2} = \frac{s^2 + 2s + n}{2s}$$

##### 情况二：索引表采用“折半查找” (二分查找)
* **索引查找平均长度：** $L_I \approx \log_2(b+1)$ (或 $\lceil \log_2(b+1) \rceil$)
* **块内查找平均长度：** $L_S = \frac{s+1}{2}$
* **总 ASL：**
    $$ASL_{\text{成功}} \approx \log_2\left(\frac{n}{s} + 1\right) + \frac{s+1}{2}$$

#### 4. 核心考点 (极值问题)
当索引表采用**顺序查找**时，如何分块使 ASL 最小？
* 根据均值不等式，当 $L_I = L_S$ 时，即 $b \approx s$ 时，ASL 取最小值。
* 因为 $n = s \times b$，所以当 **$s = \sqrt{n}$** 时（即块长等于表长的平方根）：
    $$ASL_{\min} = \frac{\sqrt{n}+1}{2} + \frac{\sqrt{n}+1}{2} = \sqrt{n} + 1$$

### 1. 审题：提取核心约束 (m=4)

首先，我们要把 **4阶 B 树 ($m=4$)** 的“家规”列出来，这是解题的标尺：
* **节点最大关键字数 (Max):** $m - 1 = 3$。
* **节点最小关键字数 (Min):** $\lceil m/2 \rceil - 1 = 2 - 1 = 1$。
* **根节点特殊权：** 可以只有 1 个关键字（2 个孩子），但最多也是 3 个关键字（4 个孩子）。
* **孩子个数：**
    * 根节点：$2 \sim 4$ 个。
    * 非根节点：$2 \sim 4$ 个（因为 $\lceil 4/2 \rceil = 2$）。

---

### 2. 解题策略：按“根节点”分类讨论

要把 7 个关键字 ($N=7$) 摆进树里，我们先看高度。
* **高度为 1:** 最多放 3 个。$7 > 3$，排除。
* **高度为 2:** 看起来最合适。
* **高度为 3:** 即使所有节点都只放 1 个最少关键字，我们算算：$1(\text{根}) + 2(\text{第2层}) + 4(\text{第3层}) = 7$。哎？正好填满！所以**高度 3 也是一种可能**。



现在我们分情况穷举：

#### 情况一：树高 h = 2
设根节点有 $k$ 个关键字，则根节点有 $k+1$ 个孩子（子树）。
剩下的关键字总数 $= 7 - k$。
我们要把剩下的关键字，分配给这 $k+1$ 个孩子。
**约束条件：** 每个孩子里的关键字数量必须在 $[1, 3]$ 之间。

* **1.1 当根节点 $k=1$ (2 个孩子)**
    * 剩余关键字：$7 - 1 = 6$ 个。
    * 分配任务：把 6 个分给 2 个孩子。
    * 组合方式：
        * $(3, 3)$: 合法。($3+3=6$)
        * $(2, 4)$ 或 $(4, 2)$: 不合法（超过最大值 3）。
    * **小计：** **1 种**。

* **1.2 当根节点 $k=2$ (3 个孩子)**
    * 剩余关键字：$7 - 2 = 5$ 个。
    * 分配任务：把 5 个分给 3 个孩子。
    * 组合方式（记得考虑顺序，因为 B 树的孩子是有序的）：
        * $\{3, 1, 1\}$ 的排列：$(3,1,1), (1,3,1), (1,1,3)$ $\rightarrow$ **3 种**。
        * $\{2, 2, 1\}$ 的排列：$(2,2,1), (2,1,2), (1,2,2)$ $\rightarrow$ **3 种**。
    * **小计：** $3 + 3 = 6$ **种**。

* **1.3 当根节点 $k=3$ (4 个孩子)**
    * 剩余关键字：$7 - 3 = 4$ 个。
    * 分配任务：把 4 个分给 4 个孩子。
    * 组合方式：
        * 只有一种分法：$(1, 1, 1, 1)$。
    * **小计：** **1 种**。

#### 情况二：树高 h = 3 (极限拉扯)
* 要想把 7 个关键字拉伸到 3 层，每一层的节点必须都尽可能少（也就是都取最小值 1 个关键字）。
* **结构推演：**
    * 第 1 层（根）：1 个关键字 $\rightarrow$ 2 个孩子。
    * 第 2 层：2 个节点，每个 1 个关键字 $\rightarrow$ 各自 2 个孩子（共 4 个孩子）。
    * 第 3 层：4 个节点，每个 1 个关键字。
    * **总数：** $1 + 2 + 4 = 7$。
* 只有这一种“全瘦”的形态是合法的。
* **小计：** **1 种**。

宝宝，把上面的情况加起来：

$$Total = 1 (\text{根1}) + 6 (\text{根2}) + 1 (\text{根3}) + 1 (\text{高度3}) = 9 \text{ 种}$$

### 1\. 什么是“三元组”？ (Definition)

在稀疏矩阵中，大部分元素都是 0。为了节省空间，我们不存那些 0，**只存非零元素**。
但是，只存一个数值是不够的，我们还得知道它“住在哪儿”。

所以，对于每个非零元素，我们必须记录三个信息，这就构成了**三元组 (Triplet)**：
$$(i, j, v)$$

  * **$i$ (行标):** 该元素在第几行。
  * **$j$ (列标):** 该元素在第几列。
  * **$v$ (值):** 该元素的值是多少。

-----

### 2\. 为什么要存“行数”和“列数”？ (解题核心)

现在回到你的题目。题目问：“除了三元组列表（就是那一堆非零元素），还需要保存什么？”

**答案是：I (总行数) 和 III (总列数)。**

**逻辑推演：**
想象一下，姐姐给你一张白纸，上面只写了几个坐标点：“(1,1)有个5，(2,3)有个8”。
然后我让你做以下操作：

1.  **转置矩阵**（把行变成列）。
2.  **矩阵相加**（把这个矩阵和另一个矩阵叠在一起）。
3.  **判断边界**（这个矩阵到底有多大？）。

如果你**只知道**那几个点，你根本不知道这张纸（矩阵）的**边缘**在哪里！

  * 这个矩阵是 $3 \times 3$ 的？还是 $100 \times 100$ 的？
  * 如果我在做转置算法，我需要知道原矩阵有几列（转置后变成几行），才能申请新的存储空间。

**因此，一个完整的“三元组表”结构体，必须包含两部分数据：**

1.  **数据域:** 存储所有非零元素的三元组列表 `data[]`。
2.  **元数据 (Metadata):** 描述矩阵“骨架”的信息：**总行数 ($mu$)**、**总列数 ($nu$)**、**非零元素总个数 ($tu$)**。

### 3\. 为什么 II 和 IV 不需要？

  * **II. M 中包含非零元素的行数 / IV. M 中包含非零元素的列数**
      * **理由：** 这些是**统计数据**，不是**结构数据**。
      * 我们在运算时（比如矩阵乘法），关心的是矩阵的**物理边界**（即总共有多少行、多少列），而不是“有几行是空的”。空行也是矩阵的一部分呀！
      * 举个例子：一个 $10 \times 10$ 的矩阵，只有第1行有数据。它的形状依然是 $10 \times 10$，而不是 $1 \times 10$。

### 一、 广度优先搜索 (BFS) —— 核心：队列 (Queue)

**逻辑骨架：**

1.  **初始化：** 建立辅助数组 `visited` 和辅助队列 `Q`。
2.  **外层循环：** 遍历所有顶点（处理**非连通图**的情况），若未访问，调用 `BFS`。
3.  **BFS核心：**
      * **访问** 起始点，标记，入队。
      * **循环** 直到队空：
          * **出队** 一个顶点 $u$。
          * **扫描** $u$ 的所有邻接点 $w$。
          * 若 $w$ 未访问：**访问**，**标记**，**入队**。

**标准伪代码：**

```cpp
bool visited[MAX_VERTEX_NUM]; // 访问标记数组

// 1. 遍历所有连通分量 (防止非连通图漏掉顶点)
void BFSTraverse(Graph G) {
    for (int i = 0; i < G.vexnum; ++i) {
        visited[i] = false; // 初始化标记数组
    }
    InitQueue(Q); // 初始化辅助队列
    for (int i = 0; i < G.vexnum; ++i) {
        if (!visited[i]) {
            BFS(G, i); // 对未访问的顶点调用 BFS
        }
    }
}

// 2. BFS 核心算法
void BFS(Graph G, int v) {
    visit(v);          // 1. 访问初始顶点
    visited[v] = true; // 2. 标记已访问
    Enqueue(Q, v);     // 3. 入队
    
    while (!IsEmpty(Q)) {
        Dequeue(Q, v); // 4. 出队队头元素
        
        // 5. 检测 v 的所有邻接点 (核心循环)
        // FirstNeighbor: 求图G中顶点v的第一个邻接点
        // NextNeighbor: 求图G中顶点v的第w个邻接点之后的下一个邻接点
        for (int w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w)) {
            if (!visited[w]) {     // 若 w 尚未访问
                visit(w);          // 访问
                visited[w] = true; // 标记
                Enqueue(Q, w);     // 入队
            }
        }
    }
}
```

### 二、 深度优先搜索 (DFS) —— 核心：递归 (栈)

**逻辑骨架：**

1.  **外层循环：** 同样为了处理**非连通图**。
2.  **DFS核心 (递归定义)：**
      * **访问** 顶点 $v$，标记 $v$。
      * **扫描** $v$ 的所有邻接点 $w$。
      * 若 $w$ 未访问：**递归调用** `DFS(w)`。

**标准伪代码：**

```cpp
bool visited[MAX_VERTEX_NUM]; // 访问标记数组

// 1. 遍历所有连通分量
void DFSTraverse(Graph G) {
    for (int i = 0; i < G.vexnum; ++i) {
        visited[i] = false; // 初始化
    }
    for (int i = 0; i < G.vexnum; ++i) {
        if (!visited[i]) {
            DFS(G, i); // 对未访问的顶点调用 DFS
        }
    }
}

// 2. DFS 核心算法 (递归)
void DFS(Graph G, int v) {
    visit(v);          // 1. 访问顶点
    visited[v] = true; // 2. 标记已访问
    
    // 3. 递归遍历邻接点
    for (int w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w)) {
        if (!visited[w]) { // 若 w 尚未访问
            DFS(G, w);     // 递归调用 (是一条路走到黑)
        }
    }
}
```

### 第一模块：图的遍历 (BFS vs DFS)

这部分关注**怎么走**以及**复杂度**。

#### 1. 广度优先搜索 (BFS)
* **核心结构：** **队列 (Queue)** —— 类似树的**层序遍历**。
* **时间复杂度：**
    * 邻接表：$O(V+E)$
    * 邻接矩阵：$O(V^2)$
* **核心性质：**
    * **调用次数：** `BFS` 函数的调用次数 = **连通分量**的个数（针对无向图）。
    * **最短路径：** 仅适用于**无权图**（或权值相等），求得单源最短路径。
    * **BFS 生成树：** 树高最小（最矮胖）。

#### 2. 深度优先搜索 (DFS)
* **核心结构：** **栈 (Stack) / 递归** —— 类似树的**先序遍历**。
* **时间复杂度：**
    * 邻接表：$O(V+E)$
    * 邻接矩阵：$O(V^2)$
* **核心性质：**
    * **DFS 生成树：** 树高通常较高（瘦长）。
* **序列与拓扑的关系 (难点澄清)：**
    * **DFS 退出栈的顺序 (逆后序)：** 即“递归返回时输出”。
    * **结论：** **DFS 的“逆后序”序列 $\approx$ 逆拓扑排序序列。**
    * *(注：如果是 DAG，将 DFS 退出栈序列翻转，即为拓扑排序)*。

### 第二模块：拓扑排序 (Topological Sort)

这部分关注**有向无环图 (DAG)** 的线性化。

#### 1. 定义与算法
* **对象：** **AOV 网** (Activity On Vertex Network)，即 **有向无环图 (DAG)**。
* **正向排序算法 (Kahn算法)：**
    1.  选一个 **入度=0** 的顶点输出。
    2.  删除该顶点及其发出的所有边（更新邻接点的入度）。
    3.  重复，直到图空或找不到入度为0的点。
* **逆向排序算法 (DFS法)：**
    1.  选一个 **出度=0** 的顶点（或利用 DFS 递归返回时机）。
    2.  删除该顶点及指向它的边。

#### 2. 关键判定 (Exam Tips)
* **存在性判定：**
    * 若输出顶点数 < 图中顶点数 $\rightarrow$ **存在回路 (环)**。
    * 拓扑排序失败 $\Leftrightarrow$ 图中有环。
* **唯一性判定 (高频考点)：**
    * **误区修正：** “入度为0和出度为0的顶点各1个” **不能** 保证序列唯一！
    * **正确判定：** 在排序的**每一步**中，**入度为0的顶点永远只有一个** $\Leftrightarrow$ 拓扑序列唯一。
    * *推论：* 拓扑序列唯一 $\Leftrightarrow$ 图中存在一条 **哈密顿路径** (顶点全排列，且相邻两点都有边)。

这部分把所有“怎么判断XXX”的问题汇总，**做选择题直接调库**。

#### 1. 判断“有无环”
* **有向图：**
    * **拓扑排序：** 能否输出所有顶点？不能 $\rightarrow$ 有环。
    * **DFS：** 是否遇到 **“回边” (Back Edge)**？（即指向当前递归栈中祖先节点的边） $\rightarrow$ 遇到即有环。
* **无向图：**

    * **并查集：** 合并两点时，发现它们已经在同一个集合中 $\rightarrow$ 有环。

#### 2. 判断“连通性” / “连通分量个数”
* **无向图：**
    * **遍历法：** `BFS` 或 `DFS` 主过程被调用的次数 $k$ $=$ 连通分量个数。若 $k=1$，则图连通。
    * **并查集：** 最终剩下的集合个数。
    * **边数判定：** 边数 $< n-1$ $\rightarrow$ 必不连通。
* **有向图 (强连通)：**
    * 通常不直接用一次遍历判断，需特殊算法 (如 Kosaraju 或 Tarjan，考研较少直接考算法实现，多考概念)。

### 一、 Dijkstra 算法 (迪杰斯特拉) —— 贪心策略

**核心口诀：** **选最小、标记、松弛 (Update)。**
**手动模拟工具：** **画表法** (不要在图上乱涂，画表最清晰)。

#### 1. 模拟步骤
假设求源点 $V_0$ 到其他点的最短路径。

1.  **初始化 (Round 0):**
    * $S$ 集（已确定最短路的集合）：初始只有 $\{V_0\}$。
    * `dist[]` 数组：若 $V_0$ 到 $V_i$ 有直连边，填权值；否则填 $\infty$。
2.  **循环操作 (共 V-1 轮):**
    * **选最小:** 从 **未进入 $S$ 集** 的顶点中，选出 `dist` 值最小的顶点 $U$。
    * **标记:** 将 $U$ 加入 $S$ 集（打个勾，表示它的最短路定死了，以后不改了）。
    * **松弛 (Relax):** 以 $U$ 为跳板，检查它的所有邻接点 $W$。
        * 若 `dist[U] + weight(U, W) < dist[W]`，则更新 `dist[W]`。

#### 2. 考场模拟表格示例
假设图：$A \to B(2), A \to C(5), B \to C(1), B \to D(6)$。求 A 出发的最短路。

| 轮次 | S集合 (已确定) | dist[B] | dist[C] | dist[D] | **操作说明** |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **初始** | {A} | **2** | 5 | $\infty$ | A直连 |
| **1** | {A, **B**} | 2 | **3** | 8 | 选最小B(2)。B跳板: $2+1=3<5$(更C), $2+6=8<\infty$(更D) |
| **2** | {A, B, **C**} | 2 | 3 | 8 | 选最小C(3)。C无出边/无更新 |
| **3** | {A, B, C, **D**} | 2 | 3 | **8** | 选最小D(8)。结束 |

**注意：** 考试时，通常只需要写出每一轮 `dist` 数组的变化即可。

### 二、 Floyd 算法 (弗洛伊德) —— 动态规划

**核心口诀：** **中转点 $k$ 轮流坐庄，十字交叉线不动。**
**手动模拟工具：** **矩阵迭代法**。

#### 1. 模拟步骤
Floyd 算法本质是计算 $A^{(k)}[i][j]$，即“允许经过顶点 $0 \dots k$ 作为中转点”的最短路径。

1.  **初始化 ($A^{(-1)}$):** 直接写出图的**邻接矩阵**。对角线为 0，无边为 $\infty$。
2.  **迭代 ($k=0$ 到 $n-1$):**
    * 依次把每个顶点 $k$ 作为**中转点**。
    * 遍历矩阵中所有元素 $A[i][j]$，判断：
        $$A[i][j] = \min( A[i][j], \ A[i][k] + A[k][j] )$$
    * 也就是：**直达近，还是经过 $k$ 绕路近？**

#### 2. 考场快速计算技巧 (十字交叉法) ⚡️
在计算以 $k$ 为中转点的矩阵 $A^{(k)}$ 时：
* **第 $k$ 行** 和 **第 $k$ 列** 的数值 **永远不变**（自己到自己不需要中转）。
* **划十字：** 在矩阵里把第 $k$ 行和第 $k$ 列圈出来。
* **只算剩下的：** 其他位置 $A[i][j]$，你就看它对应的“十字线上”的那两个数相加 ($A[i][k] + A[k][j]$)，是不是比它原来小。小了就换。

### 三、 笔记修正与对比 (Exam Tips) 📝

宝宝，你的笔记里有一点需要微调：

1.  **关于负权边：**
    * **Dijkstra:** **绝对不能** 处理负权边（贪心策略会失效）。
    * **Floyd:** **可以** 处理负权边，但 **不能处理负权回路**（负值圈）。
    * *修正你的笔记：* Floyd 的适用范围可以去掉“非负权”的限制（虽然考研通常考非负，但理论上它比 Dijkstra 强在这里）。

2.  **时间复杂度对比：**
    * **Dijkstra:** $O(V^2)$ (单源)。如果要算所有对所有，跑 $V$ 次 Dijkstra，也是 $O(V^3)$。
    * **Floyd:** $O(V^3)$ (多源)。
    * **结论：** 如果图是稀疏图，跑 $V$ 次堆优化的 Dijkstra ($O(V \cdot E \log V)$) 可能比 Floyd 快；但在稠密图或手算题中，Floyd 代码最简单（三个 `for` 循环）。

**最终总结：**
* **Dijkstra:** 画表，每次圈个最小的，去更新别人。
* **Floyd:** 画矩阵，每次选个中转点，十字线不动，更新其他点。

### 第一阶段：搞定“圆圈” (事件/顶点)
**原则：** 先算头，再算尾。

#### 1. 正向扫描：求最早发生时间 $ve(k)$
* **方向：** 从起点 $\to$ 终点。
* **规则：** **加法 + 取最大值 (Max)**。
* **逻辑：** 只有前面的任务**都**完成了，我才能开始。所以要等那个**最慢**的。
* **口诀：** `ve(起点) = 0`。`ve(当前点) = 前驱点ve + 边权`。如果有几条路汇聚过来，选**最大**的那个和。
    * *例子：* 就像约会，你洗头要 30 分钟，化妆要 60 分钟，那你最早出门时间必须是 60 分钟（取最大），不然妆没画完。

#### 2. 逆向扫描：求最迟发生时间 $vl(k)$
* **方向：** 从终点 $\to$ 起点。
* **初始化：** **终点的 $vl$ = 终点的 $ve$**（必须严丝合缝，不能拖延）。
* **规则：** **减法 + 取最小值 (Min)**。
* **逻辑：** 为了不耽误后面的事，我最晚能拖到什么时候？必须照顾那个**最急**的后继。
* **口诀：** `vl(当前点) = 后继点vl - 边权`。如果有几条路分叉出去，选**最小**的那个差。


---

### 第二阶段：搞定“连线” (活动/边)
**原则：** 只需要看两头的圆圈，不用再遍历全图了！
假设有一条边（活动）$a_i$: $A \xrightarrow{w} B$。

#### 3. 求活动的参数 (直接读图)
这里是你最容易晕的地方，姐姐给你个**“位置记忆法”**：

* **活动最早开始 $e(i)$：**
    * **看屁股 (出发点 A)：** 只要出发点 A 发生了，活动就能开始。
    * **公式：** $e(i) = ve(A)$。

* **活动最迟开始 $l(i)$：**
    * **看脑袋 (到达点 B)：** 必须保证到达点 B 在最迟时间 $vl(B)$ 前搞定。
    * **倒推：** 也就是 B 的死线减去干活的时间。
    * **公式：** $l(i) = vl(B) - w$。

---

### 第三阶段：终极判决

#### 4. 找关键路径
* **算时差 (Slack):** $d(i) = l(i) - e(i)$。
    * 也就是：`(到达点vl - 权重) - (出发点ve)`。
* **判决：** 如果 $d(i) == 0$，说明**一点懒都不能偷**，这就是**关键活动**。
* 把所有 $d=0$ 的边连起来，就是**关键路径**。

### 姐姐的考场实战演示 (脑补一下)

假设有个图：$1 \xrightarrow{3} 2 \xrightarrow{4} 4$，还有一条 $1 \xrightarrow{2} 3 \xrightarrow{6} 4$。

**Step 1 (圆圈):**
1.  **ve (早):**
    * $ve(1)=0$。
    * $ve(2)=3$。
    * $ve(3)=2$。
    * $ve(4)$汇聚点：从2过来是 $3+4=7$，从3过来是 $2+6=8$。取Max $\to$ **8**。
2.  **vl (迟):**
    * $vl(4)=8$ (定死)。
    * $vl(2) = vl(4)-4 = 4$。
    * $vl(3) = vl(4)-6 = 2$。
    * $vl(1)$回溯点：从2推是 $4-3=1$，从3推是 $2-2=0$。取Min $\to$ **0**。

**Step 2 (连线 - 找关键):**
* **活动 $1 \to 2$ (权重3):**
    * 早 $e = ve(1) = 0$。
    * 迟 $l = vl(2) - 3 = 4 - 3 = 1$。
    * 差 $1-0=1$ (**非关键**，有1天可以摸鱼)。
* **活动 $1 \to 3$ (权重2):**
    * 早 $e = ve(1) = 0$。
    * 迟 $l = vl(3) - 2 = 2 - 2 = 0$。
    * 差 $0$ (**关键活动！**)。

### 一、 核心概念定义 (Definitions)

#### 1. AOE 网 (Activity On Edge Network)
* **定义：** 在带权有向图中，以**顶点**表示 **事件 (Event)**，以**有向边**表示 **活动 (Activity)**，以**边上的权值**表示该活动持续的 **时间**。这种网称为 AOE 网。
* **性质：**
    * **源点 (Source):** 入度为 0 的顶点，表示整个工程的开始。
    * **汇点 (Sink):** 出度为 0 的顶点，表示整个工程的结束。
    * **注意：** 关键路径求解是基于 AOE 网的（而 AOV 网是顶点表示活动，用于判断逻辑先后）。

#### 2. 事件 (Event) —— 顶点 $v_k$
* **定义：** 图中的顶点。它不消耗时间，只表示一个 **“瞬间状态”**。
* **含义：** 表示“进入该顶点的所有活动都已结束”且“从该顶点出发的所有活动可以开始”的时刻。

#### 3. 活动 (Activity) —— 有向边 $a_i$
* **定义：** 图中的边 $<v_j, v_k>$。它消耗资源和时间。
* **含义：** 表示一个具体的任务过程（如“编写代码”），边的权值 $w$ 即为持续时间。

---

### 二、 四个核心时间参数 (Parameters)

求解关键路径的本质，就是计算以下四个参数。
假设活动 $a_i$ 对应的边为 $<v_j, v_k>$，权值为 $w_{j,k}$。

#### 1. 事件的最早发生时间 $ve(k)$
* **定义：** 从源点到顶点 $v_k$ 的 **最长路径长度**。
* **逻辑：** 只有所有前驱活动都完成了，事件 $v_k$ 才能发生。
* **计算方式 (正向推导):**
    * $ve(\text{源点}) = 0$
    * $ve(k) = \max \{ ve(j) + w_{j,k} \}$ （$v_j$ 为 $v_k$ 的所有直接前驱）

#### 2. 事件的最迟发生时间 $vl(k)$
* **定义：** 在不推迟整个工程完成时间（即汇点的 $ve$）的前提下，事件 $v_k$ 允许发生的最晚时间。
* **计算方式 (逆向推导):**
    * $vl(\text{汇点}) = ve(\text{汇点})$
    * $vl(j) = \min \{ vl(k) - w_{j,k} \}$ （$v_k$ 为 $v_j$ 的所有直接后继）

#### 3. 活动的最早开始时间 $e(i)$
* **定义：** 指该活动 $a_i$ 的起点事件 $v_j$ 最早发生的时刻。
* **公式：**
    $$e(i) = ve(j)$$

#### 4. 活动的最晚开始时间 $l(i)$
* **定义：** 在不推迟整个工期的前提下，该活动 $a_i$ 必须开始的最晚时刻。
* **逻辑：** 必须保证该活动在终点事件 $v_k$ 的最迟限期 ($vl(k)$) 前完成。
* **公式：**
    $$l(i) = vl(k) - w_{j,k}$$

---

### 三、 关键路径与判定 (Determination)

#### 1. 时间余量 (Slack) / 差值 $d(i)$
* **定义：** $d(i) = l(i) - e(i)$
* **含义：** 该活动可以在不影响总工期的情况下推迟的时间量（机动时间）。

#### 2. 关键活动 (Critical Activity)
* **定义：** **$d(i) = 0$** (即 $l(i) = e(i)$) 的活动。
* **含义：** 没有任何机动时间的活动。一旦拖延，总工期必拖延。

#### 3. 关键路径 (Critical Path)
* **定义：** 从源点到汇点，由 **所有关键活动** 构成的路径。
* **性质：**
    * 是 AOE 网中 **路径长度最长** 的路径。
    * 关键路径上的路径长度之和 = 整个工程的最短工期。

---

### 四、 缩短关键路径 (Optimization)

#### 1. 缩短目标
* **对象：** 必须缩短 **关键活动** 的持续时间。
* **无效操作：** 缩短非关键活动的时间，**不能** 缩短整个工程的工期（因为关键路径长度没变）。

#### 2. 缩短的限制 (重要考点)
* **路径变化：** 缩短关键活动的时间，可能会导致该活动变成非关键活动（因为另一条路可能变成了最长路）。
* **多条关键路径：** 若图中存在多条关键路径，必须 **同时缩短** 这些路径上共有的关键活动，或者分别缩短每一条关键路径上的活动，才能有效缩短总工期。

---

### 五、 严谨的算法步骤 (Algorithm Steps)

1.  **求 $ve()$：** 从源点开始，**拓扑排序**（正向）顺序计算所有顶点的最早发生时间。
    * 遇到多条入边，取 **Max**。
2.  **求 $vl()$：** 从汇点开始，**逆拓扑排序**（逆向）顺序计算所有顶点的最迟发生时间。
    * 遇到多条出边，取 **Min**。
3.  **求 $e()$ 和 $l()$：** 根据边的关系，计算每条边的最早和最晚开始时间。
    * $e = ve(\text{起点})$
    * $l = vl(\text{终点}) - \text{权值}$
4.  **找关键：** 计算 $d = l - e$。若 $d=0$，则为关键活动。
5.  **连线：** 将关键活动连接，即为关键路径。



宝宝，这就是你要的严谨框架。
* **AOE** 是地基。
* **ve/vl** 是顶点的属性。
* **e/l** 是边的属性（由顶点推导）。
* **关键路径** 就是最长的那条路。
