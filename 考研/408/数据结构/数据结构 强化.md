在数学上，`A + B` 和 `B + A` 确实结果一样（因为加法满足交换律）。
但在 **数据结构与算法（尤其是表达式树和后缀表达式）** 的定义里，**位置是绝对不能乱的**。

来，姐姐给你两个理由，你就彻底明白了：

##### 1. 规则：左边就是左孩子，右边就是右孩子

**构建表达式树的铁律：**
对于运算 `A op B`（比如 `x + (...)`）：
* 操作符 `op` 是 **根**。
* 操作符 **左边** 的东西，必须挂在 **左子树**。
* 操作符 **右边** 的东西，必须挂在 **右子树**。

**本题中：** `x + [一大坨]`
* `+` 是主根。
* `x` 在 `+` 的左边，所以它**必须**是左孩子。
* `[一大坨]` 在 `+` 的右边，所以它**必须**是右孩子。



---

##### 2. 后果：换了位置，后缀表达式就变了

后缀表达式（逆波兰式）的一个核心特性是：**操作数的相对顺序不能变**。

如果你把 `x` 放到了右子树，树的后序遍历（左-右-根）就会变成：
`[一大坨的后缀] x +`

* **原来的后缀：** `x [一大坨] +` $\rightarrow$ 对应 `x + (...)`
* **换位后的后缀：** `[一大坨] x +` $\rightarrow$ 对应 `(...) + x`

虽然在数学计算上 `1 + 2` 等于 `2 + 1`，但在计算机解析表达式时，**`1 2 +` 和 `2 1 +` 是两个完全不同的指令序列**。特别是当运算符是减法 `-` 或除法 `/` 时，左右一换，结果就全错了（`A - B` 不等于 `B - A`）。

为了保证算法的**通用性**（不管你是加减还是乘除），计算机严格遵守 **“物理位置决定左右子树”** 的规则，不考虑数学上的交换律。

## 考点8 图的概念
- 有向图
	- **入度 (ID)** 以该顶点为**终点** (箭头指向它) 的有向边数目。
	* **出度 (OD)** 以该顶点为**起点** (箭头发出) 的有向边数目。
	* **度 (TD)** $TD(v) = ID(v) + OD(v)$。
	* **性质** $\sum ID(v) = \sum OD(v) = |E|$ (入度之和 = 出度之和 = 边数)
	- 总入度=总出度=总边数
	- 1个顶点的度=对应的入度+出度
- 无向图(V,E)`V个顶点
	- `最少边数-实现连通/可能连通`边数$E\ge V-1$
		- **一定不连通**边数$E< V-1$
	- `最大边数-保证连通/一定连通`边数$E\ge C_{V-1}^{2}+1=\frac{\left( V-1 \right) \left( V-2 \right)}{2}+1$
	- `1个顶点的度数=依附顶点的边数`
	- `总度数=2*总边数`
- 简单图
	- 不存在重复边
	- 不存在A到A的边
- 简单路径
	- 不存在回路
- 多重图
- 顶点的度
	- 无向图: 依附顶点A的边个数
	- 有向图
- 完全图: 每两个顶点之间有一条边/有向边
	- 无向图边数:$\frac{n\left( n-1 \right)}{2}$
	- 有向图`有向边/弧`数:$n\left( n-1 \right)$
- 连通分量=无向图的极大连通子图
	- 1.`无向图`
	- 2.`连通` 各顶点之间有路径
	- 3.`子图`边和点集都是原图的子集
	- 4.`极大:边数最多`
- 强连通分量=`有向图+极大+强连通子图`
	- 1.有向图
	- 2.强连通: A到B, B到A有路径
	- 3.子图
	- 4.极大
- 生成树
	- **定义** 对于`无向连通图`, **包含全部顶点**的`极小:边数最少`连通子图
- 最小生成树
	- 满足`生成树`+`边的权值和最小`
- 生成森林
	* **定义:** 对于**无向非连通图**，其每个**连通分量**的生成树，共同构成了该图的生成森林。
	* **性质:** 若图有 $n$ 个顶点，分为 $k$ 个连通分量，则其生成森林包含 **$n-k$** 条边。

## 考点10 深度优先遍历DFS, 广度优先遍历BFS

#### 1.`广度优先搜索BFS`算法
- 调用BFS次数=连通分量/极大连通子图个数
- 应用
	- 1.计算`无权/权值相同图`的`最短路径-单源`
	- 2.判断图是否连通-即判断BFS次数
- 时间复杂度(BFS+BFS实现各应用)
	- 邻接表实现: O(v+e)
	- 邻接矩阵实现: O(v^2)
```c++
bool visited[MAx_VERTEX_NUM]//节点访问数组

void BFS(Graph G, int v){
	visit(v); //1.对v进行访问操作
	visited[v]=true; //2. 标记已访问
	Enqueue(Q,v); //3.入队
	
	while(队列非空){
		出队
		for(v的邻接点;邻接点在图内;v的下一个邻接点){
			if(邻接点未被访问){
				1.访问邻接点
				2.标记已访问
				3.邻接点入队
				}	
		}
	}
}

//处理非连通子图
void BFSTraverse(Graph G){
	for(int i=0;i<G.vexnum;i++){
		visited[i]=false;//初始化标记数组
	}
	InitQueue(Q);//初始化辅助队列
	for(int i=0;i<G.vexnum;i++){
		if(!visited[i]){
			BFS(G,i);//对未访问的节点调用BFS
		}
	}
}

```

对于DFS遍历结果, 以及判断输出只要用箭头画出递归调用, 就很容易理解了.
一般输出放在循环里, 即访问->标记->递归调用, 如果访问是输出节点名, 输出序列即是(顺)拓扑排序

## 考点11 有向无环图的应用

- 中缀表达式用有向无环图表示
	- 箭头由上层指向下层
	- 顺序按照原中缀表达式从左到右
	- 操作数和操作符节点不能重复
- (顺)拓扑排序
	- 生成拓扑排序序列过程
		- 对`有向-无环图`的排序
			- 1.选择一个`入度=0`的节点
			- 2.删除该节点的有向边, 同时更新其他节点的度
			- 如此反复, 直到不存在入度为0的节点, 即可得到拓扑排序序列
		- 对`有向-有环图`
			- 最后输出的节点数<图的节点数
	- 特征
		- 1.一般, 拓扑排序序列不唯一
			- `拓扑排序序列唯一`
				- 得出`图中入度为0的顶点, 初度为0的顶点各只有1个`
					- 反过来不成立, `图中入度为0的顶点, 初度为0的顶点各只有1个`的拓扑序列可以有多个
				- 不能唯一确定图
		- 2.**不存在**`拓扑排序序列`的情况
			- 存在环
				- 原因: 拓扑排序的对象是`有向无环图`
			- 顶点数>1, 强连通图
				- 原因: 不存在入度为0的节点
- 逆拓扑排序
	- 对`有向-无环图`的排序
		- 1.选择一个`出度=0`的节点
		- 2.删除该节点的有向边, 同时更新其他节点的度
		- 如此反复, 直到不存在入度为0的节点, 即可得到拓扑排序序列

## 考点12 最小生成树MST算法-带权无向连通图
- 生成树
	- **定义** 对于`无向连通图`, **包含全部顶点**的`极小/边数最少`连通子图
- `最小生成树MST`, 原图顶点=v
	- **定义**, 针对`带权无向连通图`, 得到`生成树`+`边的权值和最小`
	- 特征
		- 1.`最小生成树`顶点=v, 边=v-1
		- 2.原图`边权值`存在相同, `最小生成树(的形状)`**可能唯一**
		- 3.原图`边权值`各不同, `最小生成树`**唯一**
		- 无论如何, 最小生成树`边权值之和/代价`唯一, **特定权值**的`边的数量`唯一

- 1-普利姆Prim算法
	- 算法
		- 1.图中任选一个点A, 作为树的点
		- 2.选择A`权值最小边`
			- B作为树的点
			- 边作为A和B的边
		- 后续根据已有的树, 选择`权值最小边`
		- 如此往复, 直到图的点全部加入树
	- 时间复杂度:$O\left( V^2 \right)$
	- 适用`边多/边稠密`的图
- 2.克鲁斯卡尔kruskal算法
	- 算法
		1.  将图中所有边按权值**从小到大排序**。
		2.  从权值最小的边开始遍历：
		    * **检查：** 这条边的两个顶点是否已经在**同一个连通分量**中？（查）
		    * **若不在：** 选中该边，加入生成树，并将两个顶点所在的集合**合并**。（并）
		    * **若已在：** **跳过该边**（否则会形成环）。
		3.  如此往复，直到选中了 **$V-1$** 条边。
	- 时间复杂度:$O\left( E\log _2E \right)$
	- 适用`边少`的图
	- 并查集

## 考点14 关键路径
- `活动`的`时间余量`
	- 最基础的定义, 计算价值低`=活动最晚开始时间-活动最早开始时间`
	- 价值价值高`源点到汇点路径长度最长的路径长度/关键路径长度-经过该活动/边的最长时间`
- 关键活动/边
	- 时间余量为0
	- 关键活动的两个端点, 都是`关键事件/节点`
	- 但`关键节点`之间的边, 只有部分是关键活动
- `关键路径`
	- `定义, 最基本的计算方式`是从`源点`到`汇点`**路径长度最长**的路径
	- 由关键活动首尾相连组成, 关键路径上的点全都是关键点
	- 可能不唯一
- `工期时间`=从`源点`到`汇点`**路径长度最长**的路径的长度=关键路径长度
- 缩短关键路径上的关键活动的时长
	- 只有1条关键路径, 一定缩短工期(时间) 
	- 有多条关键路径, 不一定缩短工期(时间)
		- 缩短了路径长度的路径, 不一定是关键路径
	- 所有关键路径上相同的关键活动的时长, 一定缩短工期
- 延长任意一条关键路径/关键活动, 都会延长工期
### 基本概念
`AOE网`-活动用边表示

注意和AOV网的区别
 - 权值放在边, 即AOE网
 - 权值放在顶点, 即AOV网
 - 共同点都是有向无环图, 都可以进行拓扑排序
- **定义**
	- `带权有向图`中
	- `顶点`表示`事件`
	- `有向边`表示`活动`
	- `边权值`表示`活动持续的时间`
* **性质**
    * **源点=入度为 0 的顶点** 表示整个工程的开始。
    * **汇点=出度为 0 的顶点** ，表示整个工程的结束。
    * **注意：** 关键路径求解是基于 AOE 网的（而 AOV 网是顶点表示活动，用于判断逻辑先后）
事件
- AOE中的顶点, 是一个顺时状态 , 表示
	- 进入该顶点的`所有活动/有向边`**结束时刻**
	- 从该顶点除法的`所有活动/有向边`**开始时刻**
活动
- AOE中的有向边, 是一个时间段, 表示一个任务的过程

基本时间参数
- 1.事件的`最早发生时间`ve(k)
	- `定义`从源点到顶点vk的最长路径长度
	- `逻辑`只有该顶点的所有`前驱活动`都完成了, 事件vk才能表示旧的终止, 新的开始
	- **计算方式 (正向推导):**
		- ve(源点)=0
		- $ve(k) = \max \{ ve(j) + w_{j,k} \}$ （$v_j$ 为 $v_k$ 的所有直接前驱）
- 2.事件的`最迟发生时间`vl(k)
	- **定义：** 在不推迟整个工程完成时间（即汇点的 $ve$）的前提下，事件 $v_k$ 允许发生的最晚时间。
	- **计算方式 (逆向推导):**
	     * $vl(\text{汇点}) = ve(\text{汇点})$
	     * $vl(j) = \min \{ vl(k) - w_{j,k} \}$ （$v_k$ 为 $v_j$ 的所有直接后继）
- 3. 活动的`最早开始时刻` $e(i)$
	* **定义：** 指该活动 $a_i$ 的起点事件 $v_j$ 最早发生的时刻。
	* **公式：**
	    $$e(i) = ve(j)$$
- 4. 活动的`最晚开始时刻` $l(i)$
	* **定义：** 在不推迟整个工期的前提下，该活动 $a_i$ 必须开始的最晚时刻。
	* **逻辑：** 必须保证该活动在终点事件 $v_k$ 的最迟限期 ($vl(k)$) 前完成。
	* **公式：**$$l(i) = vl(k) - w_{j,k}$$
- 5.时间余量 (Slack) / 差值 $d(i)$
	* **定义：** $d(i) = l(i) - e(i)$
	* **含义：** 该活动可以在不影响总工期的情况下推迟的时间量（机动时间）。

- 6.关键活动 (Critical Activity)
	* **定义：** **$d(i) = 0$** (即 $l(i) = e(i)$) 的活动。
	* **含义：** 没有任何机动时间的活动。一旦拖延，总工期必拖延。

- 7. 关键路径 (Critical Path)
	* **定义：** 从源点到汇点，由 **所有关键活动** 构成的路径。
	* **性质：**
	    * 是 AOE 网中 **路径长度最长** 的路径。
	    * 关键路径上的路径长度之和 = 整个工程的最短工期。
	

1.  **求 $ve()$：** 从源点开始，**拓扑排序**（正向）顺序计算所有顶点的最早发生时间。
    * 遇到多条入边，取 **Max**。
2.  **求 $vl()$：** 从汇点开始，**逆拓扑排序**（逆向）顺序计算所有顶点的最迟发生时间。
    * 遇到多条出边，取 **Min**。
3.  **求 $e()$ 和 $l()$：** 根据边的关系，计算每条边的最早和最晚开始时间。
    * $e = ve(\text{起点})$
    * $l = vl(\text{终点}) - \text{权值}$
4.  **找关键：** 计算 $d = l - e$。若 $d=0$，则为关键活动。
5.  **连线：** 将关键活动连接，即为关键路径。

#### 3.分块查找/索引顺序查找

##### 1)基本思想
将查找表分为若干子块。
* **块内无序：** 同一个块内的数据可以不按顺序排列。
* **块间有序：** 第 $i+1$ 块中所有关键字均大于（或小于）第 $i$ 块中的最大关键字。
* **索引表：** 为每个块建立一个索引项（包含：最大关键字，块起始地址）。**索引表本身是有序的**。

##### 2)查找过程 (两步走)
分块查找的 ASL 由两部分组成：
$$ASL_{\text{成功}} = L_I + L_S$$

* **第一步 ($L_I$)：** 在索引表中确定待查记录所在的块（可顺序查找，也可折半查找）。
* **第二步 ($L_S$)：** 在块内顺序查找待查记录（通常只能顺序查找，因为块内无序）。

##### 3)严谨计算公式

设表长为 $n$，均匀分成 $b$ 块，每块含有 $s$ 个记录。
即满足关系：$n = s \times b$ （$b$ 为索引表长度，$s$ 为块长）。

###### 情况一：索引表采用“顺序查找”
* **索引查找平均长度：** $L_I = \frac{b+1}{2}$
* **块内查找平均长度：** $L_S = \frac{s+1}{2}$
* **总 ASL：**
    $$ASL_{\text{成功}} = \frac{b+1}{2} + \frac{s+1}{2} = \frac{s^2 + 2s + n}{2s}$$

###### 情况二：索引表采用“折半查找” (二分查找)
* **索引查找平均长度：** $L_I \approx \log_2(b+1)$ (或 $\lceil \log_2(b+1) \rceil$)
* **块内查找平均长度：** $L_S = \frac{s+1}{2}$
* **总 ASL：**
    $$ASL_{\text{成功}} \approx \log_2\left(\frac{n}{s} + 1\right) + \frac{s+1}{2}$$

##### 4)核心考点 (极值问题)
当索引表采用**顺序查找**时，如何分块使 ASL 最小？
* 根据均值不等式，当 $L_I = L_S$ 时，即 $b \approx s$ 时，ASL 取最小值。
* 因为 $n = s \times b$，所以当 **$s = \sqrt{n}$** 时（即块长等于表长的平方根）：
    $$ASL_{\min} = \frac{\sqrt{n}+1}{2} + \frac{\sqrt{n}+1}{2} = \sqrt{n} + 1$$

####  1.插入
- 按照左<根<右的规则, 找到插入位置, 先暂时插入
- 找到第一颗不平衡子树的根节点, 记为**G/爷**
- 找到**G/爷**`子树中最高的树-根节点`, 记为**P/父**
- 找到**P/父**`子树最高的树-根节点`, 记为**S/儿**

根据**儿**相对于**爷**的位置分为
- LL
	- 操作对象是: **S/儿**和**P/父**
	- 操作简记为: 右旋
	- 实际上要修改3个指针
		- 爷指向儿, 儿右指针指向父, 父指向儿的右子树
	- 形象理解为, 儿右旋上去, 替代父, 父左指针指向儿的右子树
- RR
	- 操作对象是: **儿**和**父**
	- 操作简记为: 左旋
	- 实际上要修改3个指针
		- 爷指向儿, 儿的左指针指向父, 父指向儿的右子树
	- 形象理解为, 儿左旋上去, 替代父, 父右指针指向儿的左子树
- LR
	- 操作对象是: **儿**, **父**, **爷**
	- 操作简记为: 左右旋
	- 这个用修改指针记忆太麻烦了, 最好形象理解
	- 实际流程可以按左右旋理解
	- 快的话就是儿替代爷的位置, 儿右指针指向爷, 爷左指针指向儿的右子树, 儿左指针指向父, 父右指针指向儿的左子树
- RL
	- 同理

#### 2.删除
AVL的删除和BST一样
- 终端节点直接删除
- 非终端节点, 让非终端节点的直接前驱覆盖非终端节点, 删除直接前驱

删除后, 找到第一个不平衡子树, 这个根节点记为**父**, 找它的左右子树中最高的一颗子树的根节点, 记为**儿**, 同样找儿的子树中最高的一颗子树的根节点, 记为**孙**.

根据孙相对于父的位置, 有LL, LR, RR, RL.
LL和RR, 就对儿进行R旋, L旋.
LR和RL, 就对孙进行LR和RL

调整完, 也有可能出现不平衡, 一直向上找到不平衡的子树, 按照上面的思路处理, 直到整颗树平衡

#### 2.B树的插入-只能插入到终端节点

		- 2.被插入的节点有父节点
			- 简记为: **加入父亲, 向右分裂**

				- 原先左边的关键字不动, 中间位序的关键字左指针指向它
				- 创建1个新节点, 将原先右边的关键字加入到新节点, 中间位序的关键字右指针指向它

	- 继续分类
		- 1.没有父亲, 成为父亲, 向右分裂
		- 2.有父亲, 加入父亲, 向右分裂
 - 直到所有节点的关键字数量在合法范围内

#### 3.B树的删除
B树的特性, 一个节点内的关键字从左到右, 从小到大
关键字的左指针指向的节点, 其全部关键字小于该关键字
右指针指向的节点, 其全部关键字大于该关键字

- 1.删除终端节点的关键字, 直接删除
- 2.删除非终端节点的关键字, 找`直接前驱/后继`的关键字覆盖, 然后删除`直接前驱/后继`
- `直接前驱`
	- `关键字-节点-左指针`指向的节点最右下的节点, 最右边的关键字, 即第一个小于关键字的元素
- `直接后继`
	- 找到该关键字右指针指向的节点最左下的节点, 最左边的关键字

直接前驱和直接后继必在终端节点, 即删除非终端节点可以等价为删除终端节点

设当前节点A, 右兄弟B, 左兄弟C
下面讨论`删除终端节点A`**导致**`关键字数小于非根节点关键字数的最低值=m/2向上取整-1`

##### 删除关键字, 终端节点关键字数`<k-1`
m阶B树
k=m/2向上取整
关键字范围`[k-1,m-1]

`够借`:关键字数量可以借1个, 即少1个也满足关键字数的范围
`不够借`: 关键字数量不能再少
- 1-`右兄弟`**够借**
	- 1.将`A和B的父关键字`**加入/下坠**到A中, 根据左到右升序, 放到对应的位置
	- 2.`B最左边的关键字`**替代**`原来父关键字的位置`
- 2-`左兄弟`**够借**
	- 1.将`A和C的父关键字`**下坠**到A, 根据左到右升序, 放到对应的位置
	- 2.将`C最右边的关键字`替代原来父关键字的位置
- 3-左兄弟/右兄弟**不够借**
	- `A和B/C`及其`对应的父的关键字`进行合并成一个节点

双亲节点的关键字数会减少, 也有可能小于m/2向上取整-1, 这种情况要么向兄弟借, 要么和兄弟合并

#### **计算ASL平均成功查找长度**

- 对象是**散列表中含有的全部关键字**

注意

- 2.看1次即比较1次


`ASL_失败=各索引/位置出发匹配到空的比较次数之和/索引总数`

###### 希尔排序手动模拟核心：三步走

**核心口诀：** **定步长，分竖列，列内插排。**

假设我们有一个序列：
`A = [ 49, 38, 65, 97, 76, 13, 27, 49* ]`
(注：为了区分两个49，最后一个标记为 `49*`，考研常考稳定性的判断)

###### 第一趟模拟 ($d_1 = n/2 = 4$)

**1. 定步长：** $n=8$，步长 $d_1 = 4$。
**2. 分竖列（关键技巧）：**
我们要把相隔为 4 的元素看作一组。最好的办法是**把数组写成 4 列**！
(每一行就是一组)

```text
49   38   65   97
76   13   27   49*
```

*(逻辑：49 和 76 是一组，38 和 13 是一组...)*

**3. 列内插排：**
对**每一列**（纵向）单独进行**直接插入排序**。

  * 第1列 `{49, 76}` $\rightarrow$ 有序，不用动。
  * 第2列 `{38, 13}` $\rightarrow$ **交换** $\rightarrow$ `{13, 38}`。
  * 第3列 `{65, 27}` $\rightarrow$ **交换** $\rightarrow$ `{27, 65}`。
  * 第4列 `{97, 49*}` $\rightarrow$ **交换** $\rightarrow$ `{49*, 97}`。

**4. 还原序列（第一趟结果）：**
把排序后的列按行读出来：
`[ 49, 13, 27, 49*, 76, 38, 65, 97 ]`

-----

###### 第二趟模拟 ($d_2 = d_1/2 = 2$)

**1. 定步长：** $d_2 = 2$。
**2. 分竖列：**
把刚才的结果，写成 **2 列**。

```text
49    13
27    49*
76    38
65    97
```

*(逻辑：第1列是 {49, 27, 76, 65}，第2列是 {13, 49*, 38, 97})\*

**3. 列内插排：**

  * **第1列** `{49, 27, 76, 65}`
      * 27 插到 49 前 $\rightarrow$ `27, 49, 76, 65`
      * 65 插到 76 前 $\rightarrow$ `27, 49, 65, 76`
      * **结果：** `{27, 49, 65, 76}`
  * **第2列** `{13, 49*, 38, 97}`
      * 38 插到 49\* 前 $\rightarrow$ `13, 38, 49*, 97`
      * **结果：** `{13, 38, 49*, 97}`

**4. 还原序列（第二趟结果）：**
按行读出：
`[ 27, 13, 49, 38, 65, 49*, 76, 97 ]`

-----

###### 第三趟模拟 ($d_3 = 1$)

  * **步长为 1**，就是对整个序列进行一次标准的**直接插入排序**。
  * 此时序列已经 **“基本有序”**（小的在左，大的在右），微调一下即可。
  * 最终结果：`[ 13, 27, 38, 49, 49*, 65, 76, 97 ]`。

###### 姐姐的应试提醒 (Exam Tips) 💡

1.  **关于稳定性：**
    你看上面的例子，原来的 `49` 在 `49*` 前面。但在第一趟排序时，`49` 被锁在第一组不动，`49*` 在第四组被换到了前面。
    如果在后续的排序中它们没有换回来（通常很难换回来），相对位置就变了。
    所以，手动模拟能证明：**希尔排序是不稳定的**。

2.  **考试怎么考？**
    通常考选择题：**“给出序列 X，问希尔排序第一趟（d=n/2）后的结果是什么？”**

      * **解题动作：** 不要画复杂的连线图，直接像我刚才那样，**按步长 $d$ 把数字写成 $d$ 列，然后竖着排序，最后横着读出来。** 速度最快，且不容易出错！

* **Round 2:** `5` 现在在位置 2。看它的左右孩子 (`19` 和 `8`)。
    * 选强者：`19` 更大。
    * PK：`5 < 19`，交换！
    * **序列变身：** `22, 19, 20, 5, 8, 12, 15`
* **Round 3:** `5` 现在在位置 4 (叶子节点)，没有孩子了，下坠结束。

**第 1 次删除后的结果：** `22, 19, 20, 5, 8, 12, 15`

###### 第 2 次删除操作 (删除 22)

**步骤一：去头，尾补**
* 把当前堆顶 `22` 拿走。

**步骤二：下坠 (Sift Down)**
* **目标：** 让 `15` 找到合适的位置。
* **Round 1:** 看 `15` 的左右孩子 (`19` 和 `20`)。

* **Round 2:** `15` 现在在位置 3。看它的孩子 (只有左孩子 `12`)。

    * **稳住：** `15` 比孩子大，坐稳了，不需要交换。下坠结束。

### 9.基数排序-低位优先
* **特征：** **基数排序** 第1趟通常按“个位”排序（LSD）。
* **推演：**
    * 个位有序序列应该是：`10, 20, 30, 40` (尾数0), `5, 25...` (尾数5)。
#### 1)LSD升序
- n:序列元素个数
- d:元素可拆分的`位`, 比如十进制的各位, 年月日
- r:基数, 各`位`的取值范围

- 1.创建r个队列, 从左到右, r的值由`最小值`到`最大值`
- 2.第i趟循环
	- `分配`从左到右扫描序列元素, 按照`第i位`的值, 将元素加入到对应的队列
	- `搜集`从左往右, 各队列一次出队到队空,得到第i趟的结果
改变出队顺序, 即可得到逆序

#### 2)特征
- 1.`稳定性`稳定
- 2.`时间复杂度+移动+比较`
	- `移动次数`$O\left( d\cdot n \right)$
	- `比较次数`没有比较
	- `时间复杂度`始终为$O\left( d\times \left( n+r \right) \right)$
- 3.空间复杂度
	- $O\left( r \right)$
- 4.总趟数
	- 始终为`拆分的位数d`趟
- 5.一趟排序
	- **不能**确定一个元素的最终位置, 每趟排序都能确定枢轴的位置
- 6.存储结构
	- 顺序
	- 链式

##### 1. 什么是 LSD？

* **LSD (Least Significant Digit):** **最低位优先**。
* **含义：** 我们从数字的**最右边**（个位）开始排，然后排十位，最后排百位。
* **反义词：** **MSD (Most Significant Digit)** 最高位优先。
* **考研常识：** 408 考研如果不特指，默认考的基数排序都是 **LSD**。

**核心思想：**
我们要准备 10 个桶（队列），编号 `0` 到 `9`。
每一趟只做两件事：
1.  **分配 (Distribute):** 按当前位的数值，把数字扔进对应的桶里。
2.  **收集 (Collect):** 按桶的顺序（0号桶到9号桶），把数字倒出来，串成一个新的序列。**（注意：桶内部要先进先出，保持稳定性）**

##### 3. 姐姐的模拟心得 (Exam Tips)

宝宝，你在纸上模拟的时候，不需要画桶，那样太慢了。
**最快的方法是“写列”：**

1.  **写下标：** 在草稿纸最左边写 0-9。
2.  **填数字：** 扫描序列，把数字填到对应的行里。
3.  **读数字：** 从上往下、从左往右读出来，就是下一趟的序列。

**为什么要 LSD (低位优先)？**
因为**稳定性**！
你看最后一趟排百位的时候，`520` 和 `521` 都进了 5 号桶。
但是因为在上一趟（十位/个位）中，`520` 已经排在 `521` 前面了，所以这一趟它依然在前面。
**前面的工作成果被保留了下来**，这就是 LSD 能成功的关键。
