### **图的存储结构 C++ 实现模板**

这是图的两种核心表示方法——**邻接矩阵**和**邻接表**——的 C++ 实现模板。你可以把它们当作你未来所有图算法的“基座”。

#### **模板一：邻接矩阵 (Adjacency Matrix)**

这种方法直观，但只适用于顶点数量不大的稠密图。

```cpp
#include <iostream>
#include <vector>

using namespace std;

// --- 邻接矩阵图 ---
class MatrixGraph {
private:
    int V; // 顶点的数量
    vector<vector<int>> adj; // 邻接矩阵，adj[i][j] = 1 表示有边

public:
    // 构造函数：传入顶点的数量
    MatrixGraph(int vertices) {
        this->V = vertices;
        // 初始化一个 V x V 的矩阵，所有元素为 0，表示没有边
        adj.assign(V, vector<int>(V, 0));
    }

    // 添加一条从 u 到 v 的边 (无向图)
    void addEdge(int u, int v) {
        // 边界检查，防止越界
        if (u >= 0 && u < V && v >= 0 && v < V) {
            adj[u][v] = 1;
            adj[v][u] = 1; // 无向图，需要设置对称的边
        }
    }

    // 打印图（用于调试）
    void printGraph() {
        cout << "Adjacency Matrix:" << endl;
        for (int i = 0; i < V; ++i) {
            for (int j = 0; j < V; ++j) {
                cout << adj[i][j] << " ";
            }
            cout << endl;
        }
    }
};
```

#### **模板二：邻接表 (Adjacency List)**

这是最常用、最高效的方法，特别是对于稀疏图。

```cpp
#include <iostream>
#include <vector>
#include <list> // 也可以用 list，这里用 vector 更常见

using namespace std;

// --- 邻接表图 ---
class ListGraph {
private:
    int V; // 顶点的数量
    vector<vector<int>> adj; // 邻接表，adj[i] 存储所有与 i 相邻的顶点

public:
    // 构造函数：传入顶点的数量
    ListGraph(int vertices) {
        this->V = vertices;
        // 初始化 V 个空的 vector，每个 vector 代表一个顶点的邻接列表
        adj.resize(V);
    }

    // 添加一条从 u 到 v 的边 (无向图)
    void addEdge(int u, int v) {
        // 边界检查
        if (u >= 0 && u < V && v >= 0 && v < V) {
            adj[u].push_back(v);
            adj[v].push_back(u); // 无向图，需要互相添加邻居
        }
    }

    // 打印图（用于调试）
    void printGraph() {
        cout << "Adjacency List:" << endl;
        for (int i = 0; i < V; ++i) {
            cout << "Vertex " << i << ":";
            for (int neighbor : adj[i]) {
                cout << " -> " << neighbor;
            }
            cout << endl;
        }
    }
};
```

-----

### **1. 语法上：只有一个微小的区别**

从 **C++ 语法**的角度来看，`class` 和 `struct` 之间**只有一个**区别：

  * **`struct` 的默认成员访问权限是 `public` (公开的)。**
  * **`class` 的默认成员访问权限是 `private` (私有的)。**

除此之外，它们在功能上是**完全等价**的。`struct` 也可以有构造函数、析构函数、成员函数、继承... `class` 能做的所有事情，`struct` 都能做。

我们看个例子：

```cpp
struct MyStruct {
    int x; // 如果不写 public/private，这里默认是 public
};

class MyClass {
    int x; // 如果不写 public/private，这里默认是 private
};

int main() {
    MyStruct s;
    s.x = 5; // 正确，因为 s.x 是 public

    MyClass c;
    c.x = 5; // 错误！编译不通过，因为 c.x 是 private
}
```

-----

### **2. 约定上：完全不同的设计哲学 (这才是关键！)**

那么，既然它们功能几乎一样，我们程序员在实际中是怎么选择的呢？这就涉及到一个**编程约定**或者说“文化”上的区别，这也是你问题的真正答案。

**我们通常用 `struct` 来做什么？**

  * 我们用 `struct` 来表示一个“**纯粹的数据集合**” (Plain Old Data, POD)。
  * 它的主要职责就是**被动地存储数据**，成员变量通常都是 `public` 的，因为它没什么需要隐藏的复杂逻辑。它就像一个**开放的工具箱**，里面的工具（数据）可以随便拿来用。
  * **例子**：我们之前写的 `ListNode`。它就是简单地存了一个 `val` 和一个 `next` 指针，没有什么复杂的内部逻辑，所以用 `struct` 非常自然和合适。

**我们通常用 `class` 来做什么？**

  * 我们用 `class` 来表示一个“**具有行为和封装的抽象概念**”。
  * 它的职责不仅仅是存数据，更重要的是**提供服务（成员函数）**，并且通过 `private` 关键字**隐藏其内部的实现细节**，以保证数据的安全和一致性。它就像一台**精密的仪器**，你只能通过它提供的按钮（`public` 函数）来操作，而不能直接动里面的零件（`private` 成员）。
  * **例子**：我们现在写的 `Graph`。它内部有复杂的邻接矩阵或邻接表 (`adj`) 和顶点数 (`V`)，我们不希望使用者能随意修改它们（比如不小心把矩阵改得一团糟）。使用者应该通过我们提供的 `addEdge` 这种安全的方法来操作图。所以，用 `class` 并把 `adj` 和 `V` 放在 `private` 里，是更符合**面向对象设计 (OOP)** 思想的。

-----

### **3. 最终结论**

所以，回答你的问题：“邻接表和邻接矩阵都是用类实现的? 而不是用结构体?”

是的，我选择用 `class` 来实现，主要是出于**编程风格和设计思想**的考虑。因为一个“图”是一个复杂的概念，它有自己的数据（顶点和边）和行为（添加边、遍历），用 `class` 来封装它，把实现细节设为 `private`，是更健壮、更专业的做法。

当然，从纯语法上讲，你用 `struct` 加上 `private:` 关键字，也能实现一模一样的效果。但按照 C++ 社区的普遍约定，`class` 更能体现这种“封装”的意图。

### **“专业版” `Graph` 类代码**

我们现在就来解决所有这些问题。

```cpp
#include <iostream>
#include <vector>
#include <limits> // 用于获取 int 的最大值

using namespace std;

// --- 通用型邻接矩阵图 ---
class MatrixGraph {
private:
    int V; // 顶点数量
    bool is_directed; // true: 有向图, false: 无向图
    vector<vector<int>> adj; // 邻接矩阵
    
    // 用一个很大的数表示两点之间没有直接相连的边
    const int NO_EDGE = numeric_limits<int>::max(); 

public:
    // 构造函数：更通用，可以指定图的类型和顶点数
    MatrixGraph(int vertices, bool directed = false) {
        this->V = vertices;
        this->is_directed = directed;
        
        // 初始化 V x V 的矩阵
        // 对角线（自己到自己）距离为 0
        // 其他默认为 NO_EDGE，表示不可达
        adj.assign(V, vector<int>(V, NO_EDGE));
        for (int i = 0; i < V; ++i) {
            adj[i][i] = 0;
        }
    }

    // 添加一条从 u 到 v 的边，带有权重 weight (默认为1)
    void addEdge(int u, int v, int weight = 1) {
        if (u >= 0 && u < V && v >= 0 && v < V) {
            adj[u][v] = weight;
            // 如果是无向图，需要设置对称的边
            if (!this->is_directed) {
                adj[v][u] = weight;
            }
        }
    }

    // 打印图（用于调试）
    void printGraph() {
        cout << "Adjacency Matrix:" << endl;
        for (int i = 0; i < V; ++i) {
            for (int j = 0; j < V; ++j) {
                if (adj[i][j] == NO_EDGE) {
                    cout << "INF ";
                } else {
                    cout << adj[i][j] << "   ";
                }
            }
            cout << endl;
        }
    }
};
```

### **在 `MatrixGraph` 中添加 BFS 遍历**

**思路**：BFS 像往水里扔一块石头，波纹一圈一圈地扩散出去。它需要一个**队列 (Queue)** 来保证这种“先进先出”的层级访问顺序。

**需要工具**：

1.  一个队列 `std::queue` (需要 `#include <queue>`)。
2.  一个“脚印”数组 `vector<bool> visited`，记录哪些顶点我们已经访问过，防止在图里兜圈子。

**代码模板（添加到你的 `MatrixGraph` 类中）**：

```cpp
#include <queue> // 记得在文件顶部包含

// ... 在 MatrixGraph 类的 public 部分添加 ...
public:
    void BFS(int startNode) {
        // 检查起点是否有效
        if (startNode < 0 || startNode >= V) {
            cout << "Invalid start node!" << endl;
            return;
        }

        vector<bool> visited(V, false); // “脚印”数组，全部初始化为 false
        queue<int> q;

        // 1. 从起点开始
        visited[startNode] = true; // 踏上第一步，留下脚印
        q.push(startNode);         // 将起点放入队列
        cout << "BFS starting from vertex " << startNode << ": ";

        // 2. 只要队列不为空，就说明还有节点待探索
        while (!q.empty()) {
            int u = q.front(); // 取出队头的节点
            q.pop();
            cout << u << " "; // 处理（访问）这个节点

            // 3. 查找 u 的所有邻居 v，并把未访问过的邻居入队
            for (int v = 0; v < V; ++v) {
                // 在邻接矩阵中，adj[u][v] != 0(或无穷) 表示 u 和 v 之间有边
                if (adj[u][v] != 0 && adj[u][v] != INT_MAX && !visited[v]) {
                    visited[v] = true; // 留下脚印
                    q.push(v);         // 放入队列，等待后续探索
                }
```

### **1. 解决“非连通图”的遍历问题**

你说的完全正确！我们目前写的 `BFS(startNode)` 和 `DFS(startNode)`，确实都只能遍历从 `startNode` 出发**能够到达**的所有顶点，也就是它所在的那个“**连通分量 (Connected Component)**”。

  * **问题**：如果图是非连通的（比如一座大城市和旁边一座孤岛），我们从大城市出发，是永远也走不到那座孤岛上去的。`visited` 数组的作用也就局限在了这一个连通分量里。
  * **解决方案**：很简单。我们的主函数，不能只从一个 `startNode` 开始就结束了。它需要一个**外层循环**，来检查并确保**每一个顶点**都被访问过。

**新的逻辑是**：

1.  在主函数里，我们创建 `visited` 数组。
2.  我们写一个 `for` 循环，遍历**所有**的顶点 `i` (from `0` to `V-1`)。
3.  在循环里，我们检查 `if (!visited[i])`。
4.  如果顶点 `i` **还没有被访问过**，就说明我们发现了一个**新的、未被探索的连通分量**。此时，我们才以 `i` 为起点，调用我们的 `DFSHelper(i, visited)` (或者一个类似的 `BFSHelper`) 来遍历完这整个连通分量。

这样，当外层 `for` 循环结束后，无论图有多少个孤立的部分，我们都能确保把它们全部走一遍。

**我们可以把原来的 `DFS` 函数改造成一个更通用的“完整遍历”版本：**

```cpp
// 在 public 部分，我们可以把原来的 DFS 改成一个更通用的版本
public:
    void DFS_Complete() {
        vector<bool> visited(V, false);
        cout << "Complete DFS Traversal:" << endl;
        // 1. 遍历每一个顶点
        for (int i = 0; i < V; ++i) {
            // 2. 如果当前顶点还未被访问
            if (!visited[i]) {
                // 3. 就从它开始，进行一次深度优先遍历，走完它所在的整个连通分量
                cout << "Component starting from " << i << ": ";
                DFSHelper(i, visited);
                cout << endl;
            }
        }
    }
```
