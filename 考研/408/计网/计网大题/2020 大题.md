### 1. 为什么 R3 (客户端侧) 是“动态”的？
* **动作方向：** **内 $\to$ 外** (Inside Initiated)。
* **谁先发起？** H2/H3 先发起。
* **逻辑：**
    * 当 H2 发出第一个包时，R3 路由器一看：“哦，你要出去。”
    * R3 **当场、临时** 在内存里查一下：“现在我有哪个公网端口空着？哦，5001空着。”
    * R3 **自动** 建立一条映射：`192.168.1.2:1001 <-> 公网:5001`。
    * **重点：** 这个映射是 **有了流量才建立**，流量停了过一会儿就**自动消失**。
    * **配置需求：** 管理员只需要开启“允许上网”的功能（SNAT），**不需要**为 H2、H3 每个人提前写好规则。

### 2. 为什么 R2 (服务器侧) 必须是“静态配置”的？
* **动作方向：** **外 $\to$ 内** (Outside Initiated)。
* **谁先发起？** H2 (外网主机) 先发起。
* **逻辑：**
    * H2 的包（请求包）到达 R2 的公网接口。
    * **此时 R2 是懵的**。如果没有任何配置，R2 会想：“谁啊？找我的 80 端口干嘛？我没开这个服务啊。” —— **直接丢弃 (Drop)**。
    * 因为 Web 服务器（192.168.1.2）躲在里面，它**还没机会**向外发包，所以 R2 的内存里**没有**关于它的动态映射记录。
* **必须做的操作：**
    * 你（管理员）必须 **提前** 在 R2 的小本本上写死一条规则（Static NAT / Port Forwarding）：
    * **“如果有外人敲我的 80 端口，请无条件把他领到里面的 192.168.1.2 去！”**
    * 这条规则必须 **24小时待命**，这就叫 **静态配置**。

### 4. 回答你的“为什么”

* **Q: 为什么不配置 R3？**
    * A: 因为在考试（和实际工程）默认语境下，路由器的 **NAT Outbound (让内网上网)** 被视为**基础功能**（通常一条通用的 `allow all` 规则涵盖所有人）。
    * 但 **NAT Inbound (发布服务器)** 是**特殊需求**，它打破了“内网由于 NAT 天然安全”的屏障，所以必须**显式、手动**地去配置那一条映射。

* **Q: R3 如果是动态的，为什么 R2 不是动态的？**
    * A: 如果 R2 也是动态的（即等待服务器先发包才能建立映射），那**外面的客户永远无法发起第一次连接**。**服务器必须被动等待连接**，所以必须有一个**永远存在**的入口，这就是静态映射存在的意义。

### NAPT (网络地址端口转换) 核心机制详解

#### 1. 基本定义
NAPT (Network Address Port Translation) 是 NAT 的一种扩展形式。它通过将内部网络的 **(私有IP地址, 源端口号)** 映射为外部网络的 **(公网IP地址, 公网端口号)**，实现多个内部主机共享一个（或少量）公网 IP 地址接入互联网。它利用**传输层端口号**来区分不同的内部主机流量。

#### 2. 两种工作模式

##### (1) 源地址转换 (SNAT) —— 动态 NAPT
* **应用场景：** 内网主机（客户端）**主动访问** 外网服务器（如：浏览网页、请求资源）。
* **触发机制：** **由内向外**的流量触发。
* **工作流程：**
    1.  **出站映射：** 当内网主机发送数据包时，NAT 路由器在 NAT 转换表中**动态建立**一个临时表项。
    2.  **地址替换：** 路由器将数据包的 **源 IP** 替换为路由器的公网 IP，将 **源端口** 替换为路由器分配的一个未使用的**临时端口**（Ephemeral Port）。
    3.  **入站匹配：** 当外网服务器回包时，路由器根据回包的 **目的端口**，查找刚才建立的临时表项，将目的 IP 和目的端口还原为内网主机的私有 IP 和端口。
* **特征：**
    * **动态性：** 映射关系随会话建立而生成，会话结束或超时后**自动老化/删除**。
    * **方向性：** 必须由内网主机先发起请求，外网主机无法凭空直接访问内网主机的任意端口。

##### (2) 目的地址转换 (DNAT) —— 静态 NAPT / 端口映射
* **应用场景：** 外网主机（客户端）**主动访问** 内网服务器（如：Web 服务器、FTP 服务器）。即“服务器发布”。
* **触发机制：** **由外向内**的流量触发。
* **工作流程：**
    1.  **静态配置：** 管理员必须**预先**在 NAT 路由器上配置一条**固定的**映射规则（Port Forwarding）。
        * 规则示例：`公网IP:公网端口 80` $\leftrightarrow$ `内网IP:内网端口 80`
    2.  **地址替换：** 当外网主机访问路由器的 `公网IP:公网端口` 时，路由器匹配静态规则。
    3.  **转发：** 路由器将数据包的 **目的 IP** 替换为内网服务器的私有 IP，将 **目的端口** 替换为内网服务器的服务端口，然后转发给内网服务器。
* **特征：**
    * **静态性：** 映射关系永久存在，无论是否有流量通过。
    * **必要性：** 若无此配置，路由器对于外网主动发起的连接请求（目的端口未在会话表中），默认行为是**丢弃 (Drop)**。

#### 3. 核心对比总结 (Key Takeaway)

| 比较维度       | 动态 NAPT (SNAT)           | 静态 NAPT (DNAT / 端口映射)   |
| :--------- | :----------------------- | :---------------------- |
| **主要角色**   | 内网是客户端 (H2/H3)           | 内网是服务器 (Web Server)     |
| **流量发起方向** | **内 $\to$ 外** (Outbound) | **外 $\to$ 内** (Inbound) |
| **映射表生成**  | **动态生成** (路由器自动处理)       | **静态配置** (管理员手动写入)      |
| **目的**     | 允许多人上网，节省公网IP            | 允许外部访问内部特定服务            |
| **配置复杂度**  | 简单 (只需开启 NAT 功能)         | 较繁琐 (需逐个服务配置 IP 和端口)    |
