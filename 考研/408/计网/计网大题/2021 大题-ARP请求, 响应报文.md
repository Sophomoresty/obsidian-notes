### 第三问：H2 收到的帧 (高能预警 ⚠️)

**你的答案：**
> “接收到的是主机H1的单播帧... 目的MAC地址 00-11-22-33-44-bb”

**姐姐的纠正：**
宝宝，这里全错了！❌
你陷入了一个**“上帝视角”的误区**。你认为 H1 知道要发给 DNS，所以直接发了一个写着 DNS MAC 地址的包，然后交换机因为不知道路所以广播了。

**错在哪里？**
请回到题目条件：**“H1 的 ARP 表... 均为空”**。

**真实逻辑推演：**
1.  H1 想要发 DNS 请求给 `192.168.1.126` (DNS服务器)。
2.  H1 **在封装链路层帧之前**，先查自己的 ARP 缓存：“我知不知道 .126 的 MAC 地址？”
3.  **H1 发现：不知道（为空）。**
4.  **关键点：** H1 此时**根本无法构建**你所说的“目的MAC为 ...bb”的单播帧！因为它不知道 `...bb` 是谁。
5.  **H1 的实际动作：** H1 只能发送一个 **ARP 请求广播帧**。
    * 内容：“谁是 192.168.1.126？请告诉我你的 MAC。”
    * 目的 MAC：`FF-FF-FF-FF-FF-FF` (广播)。
6.  交换机收到这个**广播帧**，无条件泛洪（Flood）。
7.  **H2 接收到了这个 ARP 广播帧。**

**后续流程：**
* DNS 服务器回复 ARP (单播)。
* H1 终于知道了 MAC，发送 DNS 请求 (单播)。此时交换机已经学习了 DNS 的端口（通过之前的 ARP 回复），所以**H2 此时不会收到 DNS 请求帧**。

**那么 H2 还会收到第二个帧吗？**
会！但不是你说的那个。
* Local DNS 服务器解析 `www.abc.com` 需要去外网（找根域名服务器）。
* Local DNS 需要把包发给网关（路由器 `192.168.1.1`）。
* Local DNS 查 ARP 表：空。
* **Local DNS 发送 ARP 请求广播帧**（找路由器）。
* 交换机泛洪。
* **H2 收到第二个 ARP 广播帧。**

### 💡 你的逻辑高光点 (深度解析)

**你的核心路径：**
1.  **必然事件一 (H1找DNS):**
    * H1 要发 DNS 请求 $\rightarrow$ 必须知道 DNS 服务器 MAC $\rightarrow$ ARP 表为空 $\rightarrow$ **H1 发起第一次广播**。
    * **结果:** H2 收到第 1 个帧 (ARP Request)。
2.  **必然事件二 (H1找路由):**
    * H1 拿到域名解析结果（IP地址）后，准备发 HTTP 报文 $\rightarrow$ 发现目标 IP 在外网 $\rightarrow$ 必须发给**默认网关 (路由器 R)**。
    * H1 再次查 ARP 表 $\rightarrow$ 只有 DNS 的 MAC，**没有路由器的 MAC** $\rightarrow$ **H1 发起第二次广播**。
    * **结果:** H2 收到第 2 个帧 (ARP Request)。

**结论：**
无论本地域名服务器是个什么状态（有没有缓存、要不要找根域名），**H1 自己为了完成这套流程，就至少要吼两次（广播两次）。**
