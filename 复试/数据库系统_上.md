# 第1讲 数据库系统基础概念梳理
## 表与关系
表table的组成
- 表名
- 表标题
- 表内容(值)

相关概念
*   **关系 (Relation)**  $\approx$  表 (Table)
    *   构成: 表名 + 表标题 + 表内容.
*   **关系模式 (Relation Schema)**  $\approx$  表头 (Table Header)
    *   构成: 表名 + 表标题 (即数据的逻辑结构描述).
*   **元组 (Tuple) / 记录 (Record)**  $\approx$  表内容的一行 (Row)
    *   定义: 关系中的一个具体数据实体.
*   **属性 (Attribute) / 字段 (Field)**  $\approx$  表的一列 (Column)
    *   **属性名:** 对应表标题中的元素.
    *   **属性值:** 对应表内容中的具体数据项 (Data Item).

## 数据库系统DBS的组成
- 1.`数据库DB` DataBase
	- 长期存储在计算机内、有组织的、可共享的大量数据的集合
- 2.`数据库管理系统DBMS` DataBase Management Syste
	- 位于用户与操作系统之间的一层数据管理软件 (如 MySQL, Oracle).
- 3.`数据库应用程序DBAP` DataBase Application
	- 基于数据库开发的具体应用程序
- 4.`数据库管理员DBA` DataBase Administrator
	- 负责数据库规划、设计、维护和管理的人员
- 5.`计算机/网络基本系统`
	- 硬件、操作系统等底层支持

## 数据库管理系统DBMS的核心功能-用户视角
数据库管理系统DBMS: 管理`数据库`的系统

用户通过 **数据库语言** 与 DBMS 交互
- 一条`数据库语言`等于若干条高级语言(如C)
- `数据库语言`是一个广义的概念, 指代用户与 DBMS 进行交互的所有指令集合的总称. 理论上它包含 DDL, DML, DCL 等功能部分.
	- `SQL语言`是**结构化查询语言**, 它是目前关系型数据库中最通用、最标准的一种**数据库语言的具体实现**

数据库管理系统DBMS包含以下四类功能:
- 1.数据库**定义**
	- **功能:** 定义数据库中的逻辑结构（模式）,存储结构和存取方法
	- **工具:** `数据定义语言(DDL, Data Definition Language)`
		- `数据库管理系统DBMS`提供
	- **过程:** 用户使用`数据定义语言DDL`描述建立表的格式, `数据库管理系统DBMS`按照用户的定义, 创建数据库及其中的Table
- 2.数据库**操纵**
	- **功能:** 对数据进行增 (Insert)、删 (Delete)、改 (Update)、查 (Select) 等操作.
	- **工具:**  `数据操纵语言(DML, Data Manipulation Language)`
		- `数据库管理系统DBMS`提供
		- Manipulation n.操纵
	- **过程:** 用户使用`数据操纵语言DML`描述要进行的增, 删, 改, 差等操作, `数据库管理系统DBMS`依照用户的操作描述, 执行这些操作
- 3.数据库**控制**
	- **功能:** 控制数据库中数据的使用, 哪些用户可以使用, 哪些不可以
	- **工具:** 数据控制语言/(DCL)Data Control Language`
		- `数据库管理系统DBMS`提供`
	- **过程:** 用户使用数据控制语言DCL描述对数据库要实施的控制, `数据库管理系统DBMS`依照用户的描述, 实际进行控制
- 4.数据库**存储和维护**/数据库**维护**
	- **功能:** 数据载入、转换、转储 (Backup)、恢复 (Recovery)、性能监测与分析.
	- **工具:** DBMS 提供的一系列实用程序

### DBMS的系统实现
为了支持上述功能, DBMS 在后台运行着复杂的程序模块.

DBMS的功能含有并发控制, 但**没有处理机控制** 

>SQL 是一种**声明式 (Declarative)** 语言. 用户只告诉 DBMS "我想要什么数据" (比如: `SELECT * FROM Students`), 而不告诉 DBMS "具体怎么去磁盘找这些数据".
>
>即SQL语言表述要实现的结果, 而过程需要DBMS需要去实现
* **语言编译器**
	* 将用户编写的 SQL (高级语言) 编译成 DBMS 可执行的内部指令.
* **查询实现**
	* 对于同一个逻辑操作 (例如两个表的连接 Join, 或者排序 Sort), 计算机内部存在多种具体的**算法**来实现.
		* 例如 "连接" 操作, 可以用 "嵌套循环 (Nested Loop)", 也可以用 "哈希连接 (Hash Join)" 或 "归并连接 (Merge Join)". 这些就是**基本命令的不同执行算法**.
* **查询优化**
	* 由于存在多种算法, 且不同算法在不同数据量下的效率差异巨大 (例如数据量大时, 全表扫描比索引扫描慢得多), DBMS 需要一个组件来**估算**各种执行路径的代价 (I/O 次数, CPU 时间), 并**选择**一个代价最小的执行计划 (Execution Plan). 这个组件就是查询优化器.
* **执行引擎**
	* 负责按照优化器选定的方案, 真正去调用底层算法, 操作数据并返回结果.
* **数据存储与索引**
	* 管理数据在磁盘等外存上的物理存储结构及存取路径 (Access Path).
* **通信/通讯控制**
	* 处理网络环境下的数据传输.
* **事务管理**
	* 保证事务的 ACID 特性 (原子性、一致性、隔离性、持久性), 避免并发错误.
* **故障恢复**
	* 通过日志 (Log) 和备份, 确保系统故障后数据能恢复到正确状态.
* **安全性与完整性控制**
	* 验证用户身份, 检查数据约束条件
- **应用程序接口(API)**
	- 提供应用程序使用DBMS特定功能的手段数据库数据装载、重组等实用程序
- **数据库性能分析**
	- 统计在运行过程中数据居库的各种性能数据，便于优化运行
